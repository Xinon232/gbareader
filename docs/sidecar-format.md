# gbareader V1.4 companion format and recovery

## Association and limits

Append `.sav` to the complete book filename in the same directory. `Title.txt.sav` and `Title.epub.sav` are distinct. The native library remains `/gbareader`, up to 64 discovered books; SAV files are not library entries. Source names up to 255 UTF-8 bytes remain readable; the conservative saving limit is 251 bytes, leaving room for the suffix under FatFS's 255-unit LFN limit. Names are never silently truncated to make a companion.

All source handles use `FA_READ | FA_OPEN_EXISTING`. Only the separately owned companion FIL and independent global-settings FIL are writable. There are no source renames, writes or truncates and no temporary aliases. The second FIL replaces the old 800-byte footer rollback array, rather than adding a second file plus another state buffer. The 8 KiB source window is invalidated and exclusively borrowed for state and cache readback. Export retains the existing 512-byte write scratch, parser/inflater workspace, 4096-byte checked blocks and 512-byte checksum-table window.

## Version 1 on-disk layout

Integers are unsigned little-endian. CRCs are standard finalized CRC-32/IEEE, not cryptographic authentication. No packed C struct is written to disk.

| Offset | Bytes | Meaning |
|---|---:|---|
| 0 | 1024 | State bank 0 |
| 1024 | 1024 | State bank 1 |
| 2048 | 32 + N + 4 ceil(N/4096) | Optional normalized EPUB cache |

A first TXT save can occupy only bank 0 (1024 bytes); subsequent saves use the two fixed locations, never exceeding 2048 bytes. EPUB cache/state together cannot exceed 128 MiB. There is no ever-growing save journal or per-save central directory.

Each bank:

| Relative offset | Bytes | Meaning |
|---|---:|---|
| 0 | 8 | ASCII `GBARSAV1` |
| 8 | 4 | Container format = 1 |
| 12 | 4 | Generation, 1 through 0xffffffff; exhaustion rejects further saves, no wrap |
| 16 | 4 | Physical source length |
| 20 | 4 | Source identity CRC |
| 24 | 4 | Logical source/archive length after legacy-tail handling |
| 28 | 4 | Normalized text processor version = 1 |
| 32 | 4 | Cache payload bytes, zero for no cache |
| 36 | 4 | Entire cache payload CRC, zero when absent |
| 40 | 4 | Header CRC over bytes 0 through 39 |
| 44 | 20 | Reserved, zero on write |
| 64 | 800 | Existing ASCII v3 reader state record, including its FNV checksum |
| 864 | 156 | Reserved, zero on write |
| 1020 | 4 | Bank CRC over bytes 0 through 1019 |

The highest valid matching generation wins. A damaged bank falls back to the other complete checked bank, not to embedded state. CRC/header/identity checks precede state parsing. The existing serializer/parser retains the byte anchor, 0–4 line spacing and paragraph gap as history-layout metadata (display-layout marker 4), explicit Arabic ON/OFF and up to 64 strictly increasing prior offsets. Opening always applies the global spacing/gap, never the old book values. Saved history is reused only for a valid byte anchor, matching renderer marker and identical effective spacing/gap/Arabic; otherwise that exact anchor is retained and history/page-derived information rebuilds. This does not invalidate the layout-independent EPUB text cache. BUILDING history intentionally restarts from its anchor because a partial page/scan ring was never fully serialized. Unknown display layouts retain the safe anchor but rebuild boundaries. Unknown container/text versions are not interpreted or automatically overwritten.

## Source identity and limitations

The identity CRC covers three little-endian values (physical size, logical size, source kind TXT=1/EPUB=2), followed by three physical samples of `min(512, physical_size)` bytes at offsets 0, `(physical_size-sample_size)/2`, and `physical_size-sample_size`. For EPUB it additionally covers the existing CRC of all non-owned central-directory records, excluding names under `META-INF/gbareader/`. Legacy generated bytes already in the source are not stripped and participate where sampled or reflected in lengths.

This is deliberately a cheap, bounded-content identity, not a full source hash: at most 1536 sampled physical bytes plus an EPUB metadata pass. Small sources may be sampled repeatedly. The existing ZIP/package/spine checks remain separate. Cached opening does not inflate original chapters or scan the whole normalized cache. Same-size edits outside samples, unchanged declared ZIP CRCs, CRC collisions and coordinated malicious resealing can evade this identity. External concurrent editing while a book is open is unsupported. After editing/replacing a book, move aside its old SAV. Moving/renaming an unchanged book with its companion does not invalidate the identity.

## Cache payload

The inherited `GBAREPC5` header uses internal cache format **6**, text processor **1**, original central-directory fingerprint, normalized length, combined text CRC, checksum-table CRC and header CRC. The payload is the same checked normalized representation used by V1.3, without any ZIP local/central headers:

`32-byte header | N normalized bytes | ceil(N/4096) little-endian block CRCs`

A state descriptor additionally records the CRC of this entire payload. On open, the table is streamed through bounded scratch and its CRC, combined text CRC and reconstructed payload CRC are checked. Text blocks are read and checked only when requested. Invalid header/table falls back to originals; invalid block discards the cache before original reindexing. Original normalized length must agree on a lazy fallback; a failed original read, validation failure or length disagreement never exposes the corrupt block as text.

During fresh creation/rebuilding, normalized text is exported with bounded callbacks, the block table and header are finalized, the companion is synced/closed and reopened read-only, and the entire newly written cache payload is read back sequentially against its generated CRC. This full readback occurs only when constructing/replacing the cache, not during normal cached opens or bookmarks. Only a verified state-bank publication notifies the live EpubDocument that cache persistence succeeded. Repeated saves through that same object remain state-only.

A cache rebuild may overwrite the old derived cache at the fixed offset; it does not promise recovery of a damaged old cache. State banks remain separate, and validated original chapters can regenerate the cache. A complete state without a cache is allowed. Old external format-6 caches are not read and written simultaneously for ordinary state saves.

## Transactions and failures

1. Validate pending state and the live source identity. Unknown/mismatched companions, even empty ones, are never claimed by filename alone.
2. Close any existing companion handle before opening it writable; failed closes retain/quarantine the original FIL and prohibit slot reuse. Source reading remains separate.
3. For first EPUB preparation, durably publish a state-only bank before exporting the large cache. A later failed preparation can therefore leave usable state and no valid cache.
4. Write only the inactive 1024-byte bank with the next generation, sync, close, reopen and read back its expected checked record. Report success only when the intended generation/bank CRC is read back. No normal bookmark rewrites or reads the large cache.
5. Return false on failed write/sync/close/reopen/readback. Pending UI state remains in RAM; `Saved` is not claimed just because a write request returned. Transient failed reopen can be retried on the same ReaderFile.

Failure-only cleanup reacquires the companion handle to clear FatFS's latched file error. A failed data write can allocate a cluster before advancing the visible file size; FatFS truncate at EOF would do nothing. Cleanup therefore seeks one byte beyond the prior companion length, then seeks/truncates/syncs back to that prior length. This bounded cleanup touches only the owned SAV; no source or alias deletion is used. If close/reacquisition/seek fails, truncation is short-circuited. Persistent storage failures may prevent cleanup.

Only a successful `FA_CREATE_NEW` by the same live ReaderFile, or a checked matching source-identity header, authorizes mutation. A newly created empty SAV remains retryable in that live session. After closing/restarting, an empty artifact has no identifying bytes and cannot be distinguished from an unrelated collision: it suppresses embedded state and remains byte-identical. Explicitly back it up and move it aside/reset it on a computer before trying again. Production never automatically deletes or adopts it. Torn records with a real valid matching identity header remain recoverable without adopting invalid state; returned-error cleanup often leaves zero bytes instead and is not evidence of a durable header. Unknown nonempty, mismatched or unrecognized-version companions likewise require manual backup/reset. A readable previous bank can survive a torn update; the two aligned banks are not a guarantee against whole-filesystem damage, controller write reordering or arbitrary electrical power loss. Checksums detect damage but cannot repair arbitrary media corruption.

FatFS latches source read/seek errors in `FIL.err`. A subsequent live save or uncached source access closes and reacquires that source strictly `FA_READ | FA_OPEN_EXISTING`, retaining pending state and the ReaderFile/EpubDocument objects. A failed close quarantines the still-owned FIL; a failed reopen retains session information for a later retry. The source window is invalidated and reacquired size plus sampled/central identity must match before content or companion state/cache access resumes. Recovery is bounded to one attempt per call; another read failure returns failure, and a detected size/identity change blocks this session until explicit close/open. This does not make concurrent source editing supported or add eager original-chapter validation.

## Read-only migration and precedence

- With no companion, current and legacy TXT footers and EPUB owned state/legacy tails are read with the inherited parser. TXT footer bytes stay hidden from displayed text, including the inherited footer-recognition behavior. Original source bytes remain intact.
- A successful save puts that state into the SAV. A valid embedded EPUB normalized cache is read and exported into the companion; otherwise original chapter normalization supplies it. Current embedded cache hits are now eligible for automatic companion preparation.
- Valid matching companion state wins over embedded state. Existing unreadable, invalid, mismatched or unknown companions suppress embedded state rather than reviving stale anchors/Arabic/history. An incomplete initial migration can consequently expose no saved state on reopen while the old embedded bytes remain recoverable in the untouched source.
- Deleting/moving aside a companion permits legacy fallback again. Thus deleting SAV is not necessarily a total reset for an old book; use its clean original bytes for that purpose.

## V3.0 independent global store

`/gbareader/SETTINGS0.DAT` and `SETTINGS1.DAT` are separate from every book companion. The reader does not create a missing library directory. Defaults are spacing 1, gap Full, shoulder startup Off and no remembered filename; old book values never seed the globals. The live shoulder mode initializes once at launch. Hold Up never persists; startup-only edits neither affect that mode now nor invalidate history/cache.

The latest supported global record is explicit **version 2**, 32 + N bytes, where N is 0..255. This bounded variable extension replaces the original 32-byte proposal to support the complete last-successfully-opened filename, including UTF-8 and its extension, without truncation or hash collisions. No native struct or numeric list index is stored.

| Offset | Bytes | Meaning |
|---|---:|---|
| 0 | 8 | ASCII `GBARCFG1` |
| 8 | 4 | Little-endian version = 2 |
| 12 | 4 | Nonzero generation, no wrap after 0xffffffff |
| 16 | 1 | Line spacing, 0..4 |
| 17 | 1 | Gap, None=0 / Small=1 / Half=2 / Full=3 |
| 18 | 1 | L/R startup, strictly 0 or 1 |
| 19 | 1 | N: exact filename byte length, zero means none |
| 20 | 8 | Reserved, all zero |
| 28 | N | Full base filename bytes, no NUL or path separators |
| 28+N | 4 | CRC32/IEEE of all preceding 28+N bytes |

Physical length must match exactly. Version 1 is still read at exactly 32 bytes: byte 19 and bytes 20..27 must all be zero, CRC is at 28, and no filename is remembered. Future/unknown versions are collisions, never automatically replaced. A name is matched byte-for-byte against the current scanned list, including extension and case. Matching selects/scrolls only, never opens; absence, rename or a failed scan selects index zero. A replacement book with the same filename is still that selection, not a content-identity claim.

Highest valid generation wins; equal generations prefer slot zero. A damaged partner produces a recovery warning when a valid record exists; neither usable produces defaults plus a load error (two missing files use quiet defaults). Settings close by B, Start or A on Go to writes once only if values differ from the last verified snapshot. Every successful book opening updates the filename and saves changed/pending globals; failed opens and moving the Home cursor do not. Reader Start saves position and retries globals independently. One failure never suppresses the other write or produces blanket success. Global writes do not touch book position, Arabic, SAV or cache bytes.

Saving probes the inactive slot, creates missing files with CREATE_NEW, and checks seek, complete write count, final length/truncate, sync, close, reopen and exact intended byte readback. Only then do the generation, active slot and persisted snapshot advance. A single bounded FIL and record buffer belong to the global object in EWRAM; a failed close quarantines that same FIL until a later close succeeds, never opening over it. Failed preferences/filename remain pending in RAM; there is no per-frame or per-key retry. Explicit Settings close, successful opening or Reader Start retries. Changing back to a clean verified snapshot before a save needs no record write. After an attempted write has failed verification, an uncertainty flag keeps even a reverted value dirty until verified replacement: the failed attempt may already have reached disk.

Existing unrelated, unknown-version and empty previous-process files are preserved. Only the current object's successful CREATE_NEW permits retrying an empty first-write artifact. A recognizable damaged supported record can be replaced while retaining a valid active copy; when neither copy is valid, damaged diagnostic files are not silently erased. Back up and move colliding files aside on a computer. These noncryptographic ownership/checksum checks are not protection against deliberate spoofing or concurrent external file replacement. Keep both SETTINGS files when moving preferences to another card; move both aside to reset globals. Book SAV deletion does not reset them. Two small copies improve recovery, not arbitrary media/controller/filesystem failure guarantees. The maximum record pair is 574 payload bytes; FAT allocation is larger.

## Verification scope

The normal host runner includes actual `__DEVKITARM__` ReaderFile and EpubDocument with pointer-keyed FatFS call adapters; failures cover every normal-path open/close/read/short-read/seek/write/partial-write/sync/truncate ordinal plus live retry and reopen. Native-parser tests cover cache/header/table/block CRC, identity collisions, legacy migration and repeated same-object saves. Existing Unicode/Arabic/pagination/history/layout/ZIP tests are retained.

`tests/fatfs/run.py` compiles the actual FatFS sources and mounts FAT16 images. It marks source books read-only, compares complete source bytes after saves/faults, reopens through fresh processes/mounts, compares complete normalized text and uses independent Python ZIP validation and read-only fsck. Transient-error filesystem failures are gates; persistent faults and abrupt process loss retain explicit diagnostic outputs. First-migration cases may have no active state when an incomplete SAV intentionally suppresses legacy fallback; existing valid companion updates still require complete old-or-new state.

Physical Supercard/SD operation, electrical torn sectors and exhaustive arbitrary power-loss outcomes are not claimed by host or emulator checks.
